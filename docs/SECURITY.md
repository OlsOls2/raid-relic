# Security scope and controls

This is a configured private pilot for two to four Keepers, currently three, sharing one relic. Public HTTP readers, signed EventSub chat participants, moderators and authenticated Keeper controls have different authority. Firestore is shared transactional storage. A valid webhook signature authenticates a provider delivery; chat location does not prove that someone actually joined a Twitch raid. Provider acceptance of a bot message does not prove that viewers saw it.

## Review and evidence

The October 27 source review was a quick, scoped review of nine assigned boundaries, not a complete penetration test. Parent-operated offline Node 22 fixtures reproduced all 15 baseline scenarios after fixture corrections (source225, 4.805 seconds, zero skips). Those scenarios exercised post-authentication dummy interfaces and reducers; they did not measure actual Twitch throughput. Parent source228 focused execution subsequently passed all 28 hardening regressions with zero skips, including approved archived-content erasure and moved-source privacy checks. The later bounded OAuth-state allocation change still requires fresh focused and full operator execution before publication. See the dated [quality record](QUALITY.md) and the exact publication CI for accepted cohorts; historical regression totals are not blanket security clearance.

The changes keep the existing 128 receipt/outbox and 256 presence bounds. Score receipts admit at most eight requests per actor/room during their retention window; all command types, including consent commands, also have a 32-receipt room limit. Withdrawal precedes reply admission, so full reply storage cannot prevent privacy withdrawal. Command ACKs and sharing receipts admit eight requests per actor. Excess requests do not allocate another receipt. These accounting keys are short-lived hashes, not public identities. Completion reservations can replace non-completion bookkeeping, but preserve existing completion receipts, including unknown delivery outcomes. An immutable completion-receipt marker survives delivery metadata removal. Only positively identified command rows can be evicted; ambiguous legacy rows remain protected until expiry. Invalid sharing identities and mismatched requested logins are rejected before receipt accounting or alias effects. A proven fresh signed rename/reused login revokes stale associations before reply admission, even when capacity denies a replacement grant. Full sharing storage otherwise declines admission without throwing. Outer message-proof deduplication prevents duplicate sharing work; retained minimal hashed receipts protect accepted and rate-rejected requests through alias changes.

Presence is optional proof for a moved-source participant. Saturation declines additional proof without evicting existing participants or aborting independent direct commands. Full revocation storage advances a conservative global `notBefore` watermark and invalidates older presence. This lets forgetting commit while delayed old messages remain unable to restore forgotten proof. Quotas and cooldowns are not refunded.

## Public rendering, exports and privacy

Public projections expose only approved retained engravings. Runes are generated from original numeric geometry; stored words do not become arbitrary SVG markup. Browser text uses text nodes/textContent and canvas fillText, not untrusted HTML. Public exports omit private mark-owner identifiers, held words and raw chat. Card generation rechecks the public stop, approved marks, journey and current holder before saving; races cancel export. Forgetting removes retained application associations and derived copies while preserving minimal existing quota/cooldown accounting. Already saved local PNGs cannot be recalled. See [sharing](SHARE_CARDS.md) and [membership policy](SEEKER_MEMBERSHIP.md).

OAuth scopes remain role-specific. Optional bot permissions do not silently become requirements for base grants. Access-token expiry can trigger validated before-use renewal under the existing lease; only definitive refresh rejection requires renewed consent, while transient provider failures remain temporary. Irreversible Raid POSTs are not replayed on 401. Cached control status does not acquire a fresh grant merely to display readiness.

A Twitch client ID is a public identifier, not a bearer credential. Parent previously classified seven historical scan findings as that public identifier, with zero unresolved findings at that checkpoint; this is not a claim about all future repository contents. The operator reruns release hygiene scans. Tokens, authorization codes, state cookies, raw provider bodies and private transcript entries must not be copied into reports. Raid diagnostics bound and redact sensitive input; other warnings use closed enums and structured severity. Public errors must not expose raw exceptions. Evidence is selected and sanitized; raw credential-bearing logs are not committed.

## Remaining boundaries and external gates

At 07:21 UTC on October 27 the parent operator reported that no Firestore OAuth-state TTL field was configured. Numeric expiry rejected old callbacks but did not remove abandoned documents. New allocation now uses at most 256 fixed physical slots in the existing collection, with eight deterministic candidate reads per start. Occupied live states are never overwritten; contention returns a closed 429 without issuing a new browser cookie or contacting Twitch. Slots become reusable after expiry. The random client-visible nonce remains unchanged; consumption checks the exact stored state hash, browser binding and expiry transactionally and remains one-use. Memory uses the same slot rules. This bounds new retained state storage, not request volume or existing hosting charges; starts perform bounded transactional reads rather than the former single create.

A callback may perform one additional exact legacy-document lookup to finish an already-issued flow. Existing orphan documents are not scanned, backfilled or deleted by this patch; their cleanup remains an operator decision. No TTL policy, index, background task, paid service or cloud configuration was added. See `test/oauth-state-retention.test.js` for bounded slot, collision, expiry, callback and legacy compatibility scenarios; these new tests await operator execution.

The initial formal hunting wave did not independently cover the internal Wander path. A later limited source trace follows the disabled route through raw-body purpose HMAC, timestamp/nonce validation, bounded replay records and prepared snapshot/generation CAS, then current consent, pause/ban and capability checks at commit. Existing tests are regression evidence, not a new independent audit or physical-provider proof; the formal quick-review coverage gap remains recorded. Wander remains off and its owned cron remains commented pending explicit owner GO.

Dependency/native-binary vulnerabilities, cloud IAM, proxy behavior, hosted retention and provider configuration were not independently audited here. Repository history hygiene belongs to the operator's sanitized scan process. Physical Twitch/OBS delivery and consent remain owner-observed gates. Synthetic fixtures, a zero-traffic preview and source inspection do not establish those physical results or authorize promotion. No scopes, pilot admission, schedulers, resources or paid features change in this increment.
