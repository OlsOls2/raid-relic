## Raider consent and erasure

Original signed nonbot/noncopied `!relic scores on` explicitly opts the caller's proven login into public-name scores for future completed participation. Anyone can see the name and joined count. This is separate from mymarks consent; no username resolver, mark ownership inference, provider lookup or new OAuth scope. Stable actor IDs are joined transiently inside the claim transaction to a private domain-hashed consent key. No participant row is stored for nonconsenting actors.

A consent must exist when the valid distinct vote is counted. Opting in after that vote does not retroactively count it. A pending private hop hash links that vote to its completed transfer; failed/expired votes do not increment. Both sides still use the existing distinct-user/ban/source-seen/stream/retired-source guards. Finalized old participant arrays are gone: historical participation is unknown, not zero all-time. The public row says since opt-in.

At most128 consented actors, top20 public rows, one private aggregate at most64KiB; capped score requests have minimal hashed original-message receipts for10minutes and a30-second read-reply budget (erasure has a separate budget). New opt-ins fail closed when the request register is full. Authentic original self !relic scores off always erases before receipt/rate/outbox capacity checks; its ACK is best effort and may be suppressed by those bounds. Global EventSub dedupe and existing original-command receipts remain intact. Receipts survive forget/off without retaining raw actor IDs, login or content. Cleanup is logical/lazy on trusted processing, no scheduler. After this replay window there is no permanent identity tombstone. Consent/counters/names/links are removed by off/forget/block/ban or consent-channel opt-out. Pause/resume, offline/online and stream closure preserve consent, earned counts and since; inactive operations cannot add votes/replies. Resuming never recreates actually erased entries. A signed new explicit opt-in can start again; no quota/cooldown refund. Changing a score name requires a signed self opt-in command.

Score replies have their own128-row/64KiB outbox so score traffic cannot fill gameplay ACK capacity. Durable exact-message claim precedes a single bot POST, with no401 or ambiguous retry. Queued consent acknowledgements check fresh consent; top/badges rebuild from fresh bounded state. Already sent public chat cannot be recalled. No startup/background workers.
