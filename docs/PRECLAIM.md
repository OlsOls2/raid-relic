# P1:180-second voting, raid-only transfer

Local branch implementation, not a claim of deployed/live proof. API200 acceptance opens only a provisional180-second claim window. It does not start arrival, transfer the relic, add a ring or display carried source runes on the host. Claim start/end are persisted independently from verified raid receipt/arrival start. Native countdown is external and not synchronized by this app.

Both sides may vote before the actual raid. Source originals may `!offer`; target originals may `!offer` only if their immutable actor ID was previously seen in original nonbot source chat in that exact authoritative stream. Target originals `!accept` as before. Actors cannot count on both sides. This is source-seen eligibility, not proof of actual Twitch raid membership. No username/chat text is stored in the private presence ledger or public meter.

The provisional threshold uses bounded fresh source GetStreams viewer_count when available, otherwise1. Signed actual raid viewers replace the estimate:0–2→T1;3+ capped ceil-sqrt. Up to10 distinct votes per side may accumulate provisionally; completion uses >= actual threshold and never the estimate. A matching verified raid and both actual quorums are required, even when receipt is the last trigger. Receipt cannot extend the acceptance deadline or restart arrival on duplicate confirmation. Late confirmation can record an ended confirmed handoff for narrow owner recovery but cannot revive votes or transfer. Missing/cancelled native raid with no receipt never transfers or clears accepted/unknown intent automatically.

A new manual eligible raid opens180 seconds at verified receipt/snatch. Old persisted hops without the new policy keep their90-second window, threshold and proof rules. No migration/retro lowering occurs. Claims expire strictly at the deadline (both event and receipt bounds); already-committed ACKs retain their existing30-second delivery grace. Completion triggered by raid receipt has its own aggregate exact-event ACK outbox entry, transactionally committed, claimed once before POST with no401/ambiguous retry. No startup drain or automatic raid worker.

Presence is one private current-stream document per configured channel, max256 actors/64KiB. It contains stream ID and actor ID/first-seen time only. New streams clear old proof; exact retired proof can survive closure only for verified eligible handoffs. Pause/optout/ban/forget revoke proof/contributions; no restoration of erased aliases/marks or quota/cooldown refund. Ten-minute chat GUID receipts remain separate from erasable proof. Logical presence expiry is stream lifecycle/policy, with lazy maintenance on transactions, no cleanup scheduler. Capacity fails closed atomically; ordinary chat now legitimately reads channel/mark policy and updates bounded presence plus receipt/dedupe, but does not read/write lineage/root or publish WebSocket frames.

`claimMeter` is the same safe aggregate on both overlays: start/end, offer/accept counts, threshold, provisional/awaitingRaid flags. No participant/session/intent fields. SVG arcs clamp0–1 and countdown seeks monotonic server time, with reduced-motion/static support,160px corner bounds and stale/disconnected clearing. Arrival/cues remain driven exclusively by verified `handoff` receipt time. Manual Atlas refresh/history and all existing privacy/share/CAS/fade/echo safeguards remain.

## Review074 corrections and owner steps

Countdown votes use claimStartedAt (acceptance) even if delivered after verified receipt; legacy votes still use the old start. Binding signed raid proof retains moved-offer classification, and a confirmed intent cannot rebind on another delivery or restart arrival/window. Every valid signed original raid delivery may claim only its exact pre-existing completion ACK key; this recovers a committed-but-never-dispatched completion on retry, without draining another row or retrying unknown/dispatching messages.

Presence admission now stores a minimal hashed original-chat GUID receipt with ten-minute logical expiry in the existing private event-receipt collection (memory uses the existing bounded seen map). No raw GUID/text/login is stored in that receipt, and it survives actor erasure/stream change. Presence docs retain a channel admission watermark for pause/optout/new-stream boundaries and at most256 ten-minute actor-hash revocation watermarks for forget. Forget does not move a channel-wide admission watermark or block other actors; no raw forgotten actor ID/login is retained by these guard records. Previously observed GUIDs cannot re-prove presence under a fresh envelope, and older event timestamps cannot bypass revocation even if that GUID was not observed before. A genuinely new source message after the watermark can explicitly rejoin; same-millisecond ambiguity fails closed. Logical expiry is checked on reads; memory prunes lazily and existing Firestore retention/cleanup remains separate, with no new scheduler or promise of immediate physical deletion. No unbounded per-chat array or permanent username index was added. Ordinary chat now uses one extra receipt read/write for this proof, still no lineage/root mutation or fanout.

Accepted POST finish rechecks current streams/consent/policy before opening voting. If revoked or changed, status stays irreversibly accepted but no usable preclaim/meter opens; no retry or unsafe recovery reset is introduced.
