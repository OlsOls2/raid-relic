# A two-minute Keeper setup checklist

Source 212 adds **`/start`** and an own-account **Get started in two minutes** checklist inside the existing private controls. Native/browser review and the new read-only preview are pending. It is a target for someone who already has Twitch and OBS available, not a guarantee of OAuth, moderation or installation time. No action runs automatically.

This remains a configured Keeper pilot, not arbitrary public enrollment. If your channel is not listed, contact the pilot owner through your existing private contact: they must verify and configure the account first. No passwords, stream keys or email are collected by the guide. The selector is populated by the existing validated public Keeper mapping; a query, cookie or form cannot expand admission.

1. Select **your own** configured channel on `/start`. Connect Twitch uses only the canonical application `/oauth/keeper/<configured-id>/start` route, which creates its existing signed state/nonce and matching-account callback. Do not copy a redirected Twitch URL or another account's login. A public selector never proves that you are connected or ready.
2. Open the matching private controls, expand the checklist and explicitly choose **Set up channel**, then **Opt in this channel**. These reuse the existing own-session/origin/CSRF actions. Setup reconciles the same five subscriptions and observes the stream; it does not start a raid. The approved bot grant and moderator status are still prerequisites, not installed by a tick or a copy button.
3. **Copy my OBS URL**, then add a Browser Source in OBS at 1920×1080. The URL is always canonical `/overlay/<own-id>`, never a preview WSS workaround. Optional sound remains muted until a user gesture. Copy success proves only clipboard completion; failures offer manual selection. The unchecked manual OBS confirmation is page-local, resets on reload and is explicitly not server verification.
4. If you want to receive the relic, choose **Become a Seeker** explicitly after opting in. A current holder cannot join; after passing, a former holder may rejoin. Queue membership is not proof of live/moderation/raid eligibility. Other eligible non-Seeker Keepers remain valid manual targets. Automatic Wander stays OFF and its cron commented pending explicit owner GO.

Private checklist ticks consume only the already-authenticated own status response. They expire after ten seconds and reset to unchecked on a failed read; **Refresh status** is a user action, not a background poll. A matching session tick is not a fresh grant-validation claim. Subscription ticks mean cached readiness was observed, not that every optional bot permission or future action is authorized. Existing before-use OAuth maintenance remains intact; no extra validation or token request is added to cached status. A copied URL or public profile cannot set private readiness.

The read-only review preview intentionally denies real OAuth/control writes. Its public guide can be reviewed without login; functional consent/setup/opt-in/Seeker behavior is tested only with signed local fixtures. Canonical production does not gain this UI until the owner separately approves promotion. No source-author real login, control, provider, stream, chat or raid action is performed. Cookie scope, session rotation, CSRF, admission, scopes and privacy/quota rules remain unchanged.

## Local/native review

`test/onboarding.test.js` uses actual memory and fake-Firestore runtime HTTP responses and a genuinely fresh configured third identity: wrong-account callback denial, own connection, explicit setup/opt-in/join, canonical OBS links, wrong-room/origin refusal and session expiry. Pure tests cover clipboard success/rejection, unchecked/manual labels and ten-second freshness. `scripts/browser-smoke-onboarding.js` walks the public guide then own mocked controls, including mobile widths, no automatic actions, clipboard denial, independent opt-in and Seeker steps, stale ticks and session expiry. This is not physical OBS installation or actual Twitch proof.

Optional `ONBOARD_CAPTURE=1` uses the existing complete-document tiled capture helper: `onboard-guide.png` and `onboard-guide-tile-N.png` cover the public guide; the private checklist is exercised by DOM/action assertions, not captured from a real control page. Per raw tile <4MiB, each encoded PNG ≤512KiB, aggregate ≤4MiB, at most six emitted images; helper coverage remains bounded to eight tiles per document. The operator owns exact-name extraction, native capture/viewing and publication. The bounded report is `artifacts/onboarding-browser-results.json`. No quality count or deployment is predicted here.

No dependency, paid API, service, storage, worker or scheduler is introduced. Existing hosting can still incur usage. Clips/paid features stay OFF, P7 writes remain gated, and no preview visit implies authorization to promote or schedule anything.
