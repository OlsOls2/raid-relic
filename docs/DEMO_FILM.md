# Client-only film mode

Open **`/demo/film`** on the reviewed host. Source 208 adds this route; its native browser/capture and zero-preview publication gates are pending. It is a 150-second, eight-scene fictional storyboard, not a recording of Twitch, OBS or a production journey. The permanent **FILM / SIMULATOR — no Twitch connection or real transfers** banner stays visible. All names are `demo_keeper_a` / `demo_keeper_b` fixtures; the simulated LIVE spotlight is not a Twitch observation.

The film starts playing, muted with no audio implementation. Its scenes are Send Off (0–15s), arrival (15–40s), provisional two-chat claim (40–60s, simulated completion at 55s), approved sample engraving (60–80s), Keeper spotlight (80–100s), retained journey (100–120s), replay of that same hop (120–135s), and card preview (135–150s). Only the simulated completion adds the one ring. Replay never adds history. The original relic, rune and bounded constellation sit on the existing navy/silver/gold palette; no remote art or new font is used.

**Space** pauses/resumes and **Right arrow** advances when focus is on the page. Focused buttons, links, range inputs and editable controls retain their native keyboard behavior. Play/Pause, Next, Restart and the labelled position slider are also available. At the end the film holds on its card and offers Replay. Background tabs stop the film clock and release WebGL; returning resumes from the same point without catching up. Reduced motion permanently releases the GL canvas and keeps the original SVG/count readable. The existing 35-second interactive demo and Wander demo are unchanged.

The final card is a local 1200×630 PNG preview with original relic art, a sample approved rune/word and one retained fictional hop. It uses the existing strict demo card model and permanent simulated caption, plus a FILM / SIMULATOR watermark. **Export simulated ring card** is a manual action only, uses the existing `raid-relic-demo-ring-1.png` filename and 512KiB bound, and never contacts a server. Nothing automatically downloads. Unsupported canvas/encoding produces an honest unavailable message. It does not loosen the live share-card model or claim a live holder.

Only static same-origin module/font/art GETs are required. The route is served before OAuth/store access with `connect-src 'none'`; it has no API, socket, beacon, storage, service-worker, clipboard, audio, credentials or real game actions. POSTs are rejected. It adds no dependency, scope, paid API, storage service, worker or scheduler; baseline hosting can still incur usage. Master read-only previews keep all game-mutation controls blocked. Wander and its commented scheduling remain OFF until explicit owner GO.

## Native QA and filming handoff

`test/film.test.js` covers exact scene boundaries, no premature ring, deterministic seek/backseek/restart, paused/hidden clocks, bounded catch-up, native-key exclusions and early static routing with store/SDK traps. `scripts/browser-smoke-film.js` uses a local TLS fixture and controlled presentation clock, tests actual GL frames/pixels and original decoded reduced-motion SVG, 1920×1200 / 1920×1080 / 390 / 320 layout, native controls and genuine manual PNG signatures/dimensions/pixels/watermark text. It requires zero application API/provider/storage requests. This is synthetic browser QA, not 150 seconds of real-time reliability proof and not physical stream evidence.

Optional **`FILM_CAPTURE=1`** uses the existing complete-document bounded tile helper for the spotlight and card scenes: `film-story.png` / `film-story-tile-N.png`, and `film-card.png` / `film-card-tile-N.png`. No full-page raster is allocated. Each raw tile is below 4MiB, encoded PNG ≤512KiB, at most six emitted PNGs and 4MiB cumulative output; helper coverage remains at most eight tiles per document. The operator must allow the exact emitted names, verify full coverage and actually view the frames before publication. The report is `artifacts/film-browser-results.json` with bounded closed diagnostics. No current native count or publication is claimed here.

The planned source-208 review is a separate zero-traffic, master-read-only preview with P7 five OFF, Seekers ON, Wander/clip/paid OFF. The parent operator owns native QA, actual captures, Git/CI and publication; this source work does not promote production or operate real controls/streams/chat.
