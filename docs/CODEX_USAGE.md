## Early implementation narrative (historical)

Raid Relic is a Node.js HTTP service targeting Cloud Run with Firestore production persistence. Webhook authentication verifies the exact raw Twitch EventSub body with timing-safe HMAC comparison, timestamp replay checks, transactional event dedupe, bounded parsing and raw UTF-8 challenge responses. Memory and injected fake-Firestore stores exercise the same reducers without real accounts or cloud operations.

A single global relic registry coordinates Keeper consent, authoritative stream IDs, Send Off intent leases and two-chat claims. Raid API acceptance is not travel. A verified eligible raid receipt opens an app-local 90-second claim window; distinct nonbot actors must reach both source `!offer` and host `!accept` thresholds. Transfer, lineage stop, growth ring and both mark contexts commit atomically. The threshold uses signed viewer count, capped at 10 per side; presence in a chat does not prove actual raid membership. External HTTP never runs inside a Firestore transaction. Dispatch markers and exact-intent worker claims prevent automatic repeat raids after accepted or ambiguous outcomes.

Original rune geometry, receipt-seeking arrivals, reduced motion, muted gesture-only procedural audio and dual read-only overlays present actual state. Atlas shows completed retained history, with literal approved-text search. Recap downloads are local snapshots; privacy removals cannot recall files already downloaded. Forge's public path is a deterministic design template, not live relic customisation. Chronicle defaults to handwritten fiction. Optional model paths require both off-default cost gates, a key and explicit authenticated action; no actual paid Chronicle/Forge calls or cost/token-usage measurements are claimed here.

Pending mark text stays private. Approval controls public projection; forget, block, veto and opt-out purge retained associations/content without quota refunds or restoring forgotten marks. Self-history sharing is a deliberate public-chat opt-in: signed original `chatter_user_id` joins stored mark author IDs, while signed `chatter_user_login` supplies the capability-bound self-name. Entered text/display names never authenticate anyone. A short-lived encrypted capability and private nonce grant authorise fresh surviving approved history only, not an arbitrary public username index, login session or complete lifetime route.
