# Community share cards — source 205, parent native QA pending

Use the existing **Download ring card Stop N** button on Atlas, or either orientation under a Keeper's recorded arrival. The card's original relic art remains the main subject. It now separates **Keeper at this stop** from **Current holder at export**, shows the retained completed-hop count, up to eight approved engraving words with locally derived original runes, and a quiet bounded journey. It does not infer today's holder from an old stop. Unknown holder is labelled “not recorded”; missing/inconsistent stop or route metadata refuses export.

Atlas remains 1200×630; Keeper landscape remains 1200×675 and vertical 720×1280. PNGs are capped at 512KiB. Existing per-stop/Keeper filenames, demo holder gate, simulated filenames, permanent demo/simulator watermarks, completion-time edition, audience/Wander labels, manual click, eight-second abort and cancellation controls remain. The backend archive is still at most 16 stops; the card explicitly labels how many retained route entries and engravings it pictures. Decorative 17/42/120 examples never become recorded history. No server renderer, image/model API, storage, worker, new dependency, remote art or font is introduced.

Exports read the uncached exact public stop, recap route and current receiving holder, validate their association and mode, and construct a strict closed model. Every public engraving is checked against bounded normalized word/one-emoji rules; only the first eight validated words reach canvas. Original rune coordinates derive locally from the same SHA-256 seed as the approved mark renderer. Raw supplied SVG/HTML, participant identifiers, private held marks and arbitrary image URLs never enter canvas. No server authority module is imported into the public/demo graph.

After PNG encoding, export rereads the exact stop, route and holder and compares structural public content; Keeper export also rechecks that its profile/record remains public and unchanged. Removed stops, changed words, erasure/veto/opt-out projection changes, moved holder/route, cancellation or stale page generation refuse the download. This is a final fresh client comparison, not a transactional guarantee over future server changes. Saved user downloads cannot be recalled. The demo uses its existing fictional model without any new API, network or storage access.

`test/share-card.test.js` checks closed bounds, current/recorded distinction and changing/removed/held metadata. `scripts/browser-smoke-share-card.js` uses two actual signed synthetic hand-offs and native manual download clicks to decode PNG signatures/dimensions/colored pixels, inspect actual canvas text calls, check two stop filenames and both Keeper orientations, test 320/390/1280 controls, and erase an engraving during export to require zero stale downloads. It adds no production test hook or fake canvas output. Parent native execution is pending; local source checks are not browser or live proof.

Optional test-only `SHARE_CARD_CAPTURE=1` saves exactly three actual downloaded byte streams: `share-atlas.png`, `share-keeper-landscape.png`, `share-keeper-vertical.png`, each ≤512KiB and ≤4MiB raw raster. The parent must explicitly allow these fixed names and view them. Results go to the bounded `artifacts/share-card-browser-results.json`; no raw DOM/errors/credentials or download strings are reported. Existing complete capture tiles and all resource/sandbox limits remain unchanged.
