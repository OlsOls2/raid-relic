## Narrow source correction

`src/marks.js` retains the limit of 16 sessions. Only when a new stream needs room, it can reclaim one session that is explicitly closed, is not the previous current context, has zero retained marks and has zero viewer counters. Open sessions, current-session quota, approved or pending retained marks, blocks and cooldowns are not discarded to make space. The previous context is closed through the existing transition logic. Same-stream context refresh remains idempotent.

If every session retains data, authoritative lifecycle/context can still advance without preallocating an empty mark session. Existing `reduceMark` returns a bounded refusal when the current context has no available session; it does not collect marks, reset another stream's quota or throw merely because the retained session list is full. Privacy erasure can still remove retained content. A later context synchronization can allocate space only after a qualifying empty inactive session exists. No mark/history truncation or session-limit increase is introduced.

Production replay protection remains in the existing lifecycle stream IDs, ordering, closed-through boundary and closed-ID set. Compacting empty mark-session containers is not permission to revive an old stream. The trusted raw context setter is not an untrusted stream-event authorization interface. Tests explicitly deliver an old compacted stream ID through the signed application route and require the current stream to remain unchanged.

## Bounded closed-ID rollover

The related lifecycle closure limit is addressed in `src/lifecycle.js`: when recording a new closed stream into a full 16-ID set, the oldest ID is removed only after persisting a monotonic private `closedStartFence`. It conservatively covers the prior fence, closed-through timestamp, latest authoritative lifecycle timestamp and closing stream's start. This covers legacy IDs whose individual start timestamps were never retained. Stream admission requires a start strictly newer than this fence, regardless of the same-second allowance or CAS/Helix observation path. A live replacement must also pass the fence that closing the old stream would establish before either transition occurs.

This intentionally declines ambiguous starts at or below the fence, even with a fresh delivery timestamp or a formerly unseen ID. Recovery requires a genuinely newer provider stream start, not a manual database-state edit; no ID or start time is invented. The tradeoff can be conservative when a legacy or delayed observation's receipt is later than its stream start. Duplicate closure or offline heartbeat does not itself advance the eviction fence because no new closed ID is added. Existing closed-through/lifecycle ordering rules still apply. The set remains at most 16 IDs; marks, history, quota, registry and consent are not rolled over with it.
